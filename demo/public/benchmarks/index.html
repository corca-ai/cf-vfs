How these numbers are measured

Each cell is the median of three runs after one full warmup. Cache order alternates. Times are measured by the Worker around one Durable Object RPC call and include dispatch, storage, and operation assertions. Full-body verification and teardown run outside that timer.

“Metadata cache” uses the existing optional 4,096-entry cache. Both columns use the same persistent SQLite VFS and inline file bodies. File bodies are approximately 0.8 KiB. This is not an APFS or native Git CLI comparison.

Git uses isomorphic-git 1.43.1. Add stages every file in batches of 32 to bound concurrent compression and stay within the isolate memory limit. The shell tables include local clone, push and pull. Coding sessions connect local clone, edits, additions, deletions, partial staging, commits and branch checkout. Mixed sessions include four poorly compressible 256 KiB files. Recovery checks inject capacity/write failures and cancellation, then retry and verify committed bytes; the serialized two-shell check uses the same room queue as the demo. The checkout probe repairs partial files with explicit git checkout --force. R2 transfers and browser latency are not included. A different file size or repository can behave differently. Very short calls can round to zero on the platform clock.

“Stat after one overwrite” overwrites one warmed file then stats every file. “Status after edit” includes one differently sized edit. “Diff” reads the original blob and working file and computes a line diff. “Copy subtree” uses the existing recursive VFS copy operation. Every final file body is checked before publishing the result.

The result lives at /benchmarks/latest.json in an isolated benchmark VFS. Its actual file modification time controls the next run.
